# API contract

Базовый URL: `http://localhost:8000/api/v1`.

## 1. Пакетная обработка — основной метод

`POST /parse/batch`

Запрос:

```json
[
  {
    "id": "rec_00417",
    "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70"
  }
]
```

Ответ: `200 OK` и массив результатов в исходном порядке.

```json
[
  {
    "id": "rec_00417",
    "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70",
    "province": "Алматы",
    "city": "Алматы",
    "district": null,
    "living_area": null,
    "street_type": "микрорайон",
    "street_name": "Аксай 3а",
    "house": "59",
    "apartment": "70",
    "entrance": null,
    "floor": null,
    "landmark": null,
    "confidence": 0.87
  }
]
```

## 2. Один адрес

`POST /parse` принимает один объект того же формата и возвращает один объект.

## 3. Файл

`POST /parse/file` принимает multipart-поле `file`:

- JSON: массив объектов `{id, raw_address}` или объект `{ "items": [...] }`;
- CSV в UTF-8: обязательные колонки `id`, `raw_address`.

Ответ — такой же массив, как у `/parse/batch`.

## 4. Проверка сервера

`GET /health` возвращает `200 OK`, когда backend и PostgreSQL готовы.

## HTTP-статусы

- `200` — адрес обработан;
- `413` — превышен размер batch или файла;
- `415` — формат файла не JSON/CSV;
- `422` — отсутствуют `id` или `raw_address`;
- `503` — PostgreSQL недоступен при проверке `/health`.

Парсер не возвращает `201`, потому что эти методы вычисляют результат, а не
создают отдельный серверный ресурс.
