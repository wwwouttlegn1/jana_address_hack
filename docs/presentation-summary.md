# JANA ADDRESS — материалы для презентации

## Краткое описание проделанной работы

JANA ADDRESS — веб-приложение для нормализации адресов доставки. Пользователь
вводит адрес в свободной форме или загружает JSON/CSV, а система преобразует
строку в отдельные поля: область, город, район, жилой массив, тип и название
улицы, дом, квартира, подъезд, этаж и ориентир.

Решение состоит из трёх частей:

1. React-интерфейс оператора для ручного ввода, пакетной загрузки, просмотра,
   исправления и экспорта адресов.
2. FastAPI-backend с REST API, валидацией Pydantic и модульным rule-based
   парсером русских и казахских адресов.
3. PostgreSQL-справочник, по которому resolver уточняет город, район, жилой
   массив и улицу. При неоднозначном совпадении система не придумывает значение,
   а оставляет поле пустым и снижает уверенность.

Пайплайн решения:

`React → REST API → FastAPI → парсер → resolver → PostgreSQL → сохранённый результат`

## Какие ресурсы были использованы

### Технологии

- Python 3.11+;
- FastAPI и Uvicorn;
- Pydantic для проверки входных и выходных данных;
- SQLAlchemy Async и asyncpg для PostgreSQL;
- Alembic для миграций;
- React 19 и TypeScript;
- Vite и Tailwind CSS;
- pytest для автоматических тестов;
- Git и GitHub для совместной работы команды.

### Данные

- OpenStreetMap — источник адресных объектов и административной иерархии;
- собственный подготовленный справочник Казахстана;
- тестовые адреса из кейса на русском и казахском языках;
- форматы JSON и CSV для пакетной обработки.

В PostgreSQL загружено 210 276 записей:

- 20 регионов;
- 310 районов;
- 8 351 населённый пункт;
- 15 017 географических объектов;
- 95 511 сегментов улиц;
- 8 960 жилых массивов;
- 1 152 административные территории;
- 80 955 альтернативных названий и языковых вариантов.

OpenStreetMap не является официальным КАТО. Данные используются с обязательной
атрибуцией OpenStreetMap, а неоднозначные совпадения обрабатываются осторожно.

## Какие результаты получили

- реализован разбор одного адреса, массива адресов и файлов JSON/CSV;
- поддержаны русские и казахские обозначения адресных компонентов;
- исходные записи не теряются даже при низкой уверенности;
- справочник PostgreSQL подключён к рабочему API;
- результаты разбора и ручные исправления сохраняются в PostgreSQL и
  восстанавливаются после обновления страницы;
- resolver восстанавливает отсутствующую административную иерархию, когда
  совпадение однозначно;
- для каждой записи рассчитывается `confidence` от 0 до 1;
- записи с низкой уверенностью визуально отмечаются для проверки оператором;
- frontend показывает таблицу результатов, поиск, ручное исправление,
  аналитику и экспорт JSON;
- API и frontend соединены, CORS проверен;
- автоматические backend-тесты и production-сборка frontend проходят успешно.

## Что показать на демонстрации

1. Открыть интерфейс и вставить несколько адресов разного формата.
2. Показать, как одна строка превращается в структурированные поля.
3. На примере «мкр Аксай 3а» показать восстановление района и жилого массива
   из PostgreSQL-справочника.
4. Загрузить JSON или CSV и показать пакетную обработку.
5. Исправить сомнительное поле вручную и экспортировать результат.
6. Перейти в аналитику и показать заполненность полей и количество адресов,
   требующих проверки.

## Практическая ценность

Структурированные адреса позволяют считать аналитику по городам и районам,
автоматически определять зоны доставки, уменьшать число звонков курьера клиенту
и повышать качество данных без изменения исходной системы заказов.
