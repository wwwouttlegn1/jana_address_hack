# API contract

Базовый URL: `http://localhost:8000/api/v1`.

## 1. Пакетная обработка — основной метод

`POST /parse/batch`

Запрос:

```json
[
  {
    "id": "rec_00417",
    "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70"
  }
]
```

Ответ: `200 OK` и массив результатов в исходном порядке.

```json
[
  {
    "record_id": "55ea3f16-3a71-4d10-9d8d-4ed9f3eb85b6",
    "id": "rec_00417",
    "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70",
    "province": "Алматы",
    "city": "Алматы",
    "district": null,
    "living_area": null,
    "street_type": "микрорайон",
    "street_name": "Аксай 3а",
    "house": "59",
    "apartment": "70",
    "entrance": null,
    "floor": null,
    "landmark": null,
    "confidence": 0.87,
    "needs_review": false
  }
]
```

## 2. Один адрес

`POST /parse` принимает один объект того же формата и возвращает один объект.

## 3. Файл

`POST /parse/file` принимает multipart-поле `file`:

- JSON: массив объектов `{id, raw_address}` или объект `{ "items": [...] }`;
- CSV в UTF-8: обязательные колонки `id`, `raw_address`.

Ответ — такой же массив, как у `/parse/batch`.

Все результаты `/parse`, `/parse/batch` и `/parse/file` сохраняются в таблице
`address_records`.

## 4. Сохранённые адреса

`GET /records?limit=500` возвращает последние сохранённые результаты. Frontend
вызывает этот метод при открытии страницы.

`PATCH /records/{record_id}` сохраняет исправленные поля. Тело запроса может
содержать только изменяемые компоненты адреса, например:

```json
{
  "district": "Медеу ауданы",
  "entrance": "2",
  "floor": "5"
}
```

## 5. Проверка сервера

`GET /health` возвращает `200 OK`, когда backend и PostgreSQL готовы.

## HTTP-статусы

- `200` — адрес обработан;
- `413` — превышен размер batch или файла;
- `415` — формат файла не JSON/CSV;
- `404` — сохранённая запись не найдена;
- `422` — отсутствуют обязательные поля или неверен формат;
- `503` — PostgreSQL недоступен при проверке `/health`.

Методы разбора возвращают `200`: клиент сразу получает готовый результат, а
сохранение в PostgreSQL является частью этой же операции. `record_id` в ответе
подтверждает, что результат записан в базу.
